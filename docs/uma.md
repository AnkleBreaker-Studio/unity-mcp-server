# UMA integration

UMA is optional. The bridge exposes the same 16 UMA routes in every project; without an available integration, they return an error with `umaInstalled` and `integrationAvailable: false`. They no longer fall through to an unknown endpoint. Install UMA and enable the `UMA_INSTALLED` scripting define to compile its separate editor assembly.

The main bridge assembly no longer references `UMA_Core` or `UMA_Core_Editor`. Those references belong to `AnkleBreaker.UnityMCP.UMA.Editor`, which is constrained by `UMA_INSTALLED`. Existing route names, argument schemas and the public `MCPUMACommands` facade remain unchanged. Recipe parsing uses the bridge's existing JSON parser, without adding a Newtonsoft dependency.

## Version differences

The adapter accepts the single-slot result returned by UMA 2 and the slot collection returned by UMA 3. It processes only the slots generated by that call. Legacy slot material fields are populated when present; UMA 3 resolves materials through overlays. Logical names are written through the version's serialized fields, and slot/overlay name hashes are updated immediately.

Renaming a slot or overlay updates wardrobe recipe references in the v1, v2 and v3 JSON layouts, including recipes with empty newer-format arrays or null slot entries. A dry run describes propagation without applying it. Invalid names and destination collisions fail before references change; the file rename must succeed before dependent writes are applied. This is not a transaction across all assets: later failures and individual recipe parsing errors still require checking the response's error/propagation details.

Slot creation no longer deletes an unrelated `Assets/Assets` directory or an `Assets` directory under the output folder. Generated files are moved with checked errors; a failed move preserves the remaining generated folder. Existing output files are not overwritten. Some files can already have moved before a later move fails, so inspect the reported paths before retrying.

## Evidence

The [validation report](validation/unity66-uma.json) records these checks on Windows, Unity **6000.6.2f1**, with the official [UMA V3.1f1 release](https://github.com/umasteeringgroup/UMA/releases/tag/V3.1f1). That archive's embedded package manifest reports **3.0.4**; the release tag and manifest version are recorded separately.

- Enabling `UMA_INSTALLED` reproduced 42 compiler errors in the previous plugin. The updated integration compiles and runs.
- A two-submesh skinned model produces two slots, overlays and a wardrobe recipe. Registration, library inspection and recipe verification pass.
- Race duplication/editing and body-slot/base-recipe creation pass. The synthetic model is a prefab with one weighted bone; this does not validate FBX importer settings, humanoid TPose extraction, rendered avatars or runtime equipment.
- Renaming reproduces and fixes stale slot/overlay hashes, skipped v1/v2 references and reference changes after a rejected destination collision. The earlier v3 propagation omission is also covered.
- A sentinel directory survives all three slot-generating workflows. A repeated slot creation rejects the collision, preserves existing slot files byte for byte and retains the generated folder.
- The runner removes its fixture assets and restores the Global Library file. All 16 facade methods return the expected availability error both without UMA and with UMA installed but its integration define disabled.
- The minimal-project queue health suite still passes. A separate compiler-only check passes against Unity 2021.3.18f1 assemblies with UMA disabled; it does not validate optional UMA compilation there.

UMA 2 API compatibility is based on the upstream source contract and compatibility branches, including the [2.14f6 slot fields](https://github.com/umasteeringgroup/UMA/blob/v2.14f6/UMAProject/Assets/UMA/Core/StandardAssets/UMA/Scripts/SlotDataAsset.cs) and optional `GetAllAssets` argument. An actual UMA 2 import/run has not been performed. Older Unity editor execution remains deferred by maintainer direction.

## Reproduce

Use a closed, disposable Unity project with the plugin from this branch, the official UMA V3.1f1 archive imported, its required dependencies resolved, and `UMA_INSTALLED` enabled. The fixture uses the release's `Human Male 3.0` race. Add a `.unity-mcp-validation` marker at the project root, then run from the plugin repository:

```powershell
./tools~/validate-uma.ps1 -EditorPath 'C:/Program Files/Unity/Hub/Editor/6000.6.2f1/Editor/Unity.exe' -ProjectPath 'C:/UnityMcpValidation/UMA66'
```

The script starts Unity in hidden batch mode and writes `Library/McpUmaValidation.json` plus `uma-validation.log`. It requires the marker and refuses an open editor. The runner refuses existing fixture folders, creates temporary assets, rebuilds the Global Library during rename checks and restores its saved index file on completion. It does not download UMA or change the project's dependencies/defines. Run the separate ordinary queue and live MCP suites for transport coverage; this UMA suite invokes the actual plugin facade inside Unity.

With UMA installed and `UMA_INSTALLED` disabled, add `-Suite Unavailable` to check all 16 diagnostics. This writes `Library/McpUmaUnavailableValidation.json` and creates no workflow assets. Re-enable the define before the ordinary workflow suite.
